AI 回報功能做完了，Eva Chu 打開專案一看，找不到那個功能。她追問改了哪裡，Agent 才承認還沒做完。

11 月 21 日，我在台大綜合教學館聽 Eva 在 GatherConf 2026 分享她用 Google Antigravity 做 Side Project 的經驗。她講到這段時，我想到自己做前端時也會遇到的情況：畫面看起來能跑，測試卻沒涵蓋使用者真的會走的流程。換成 AI 協作，這個落差又多了一層，因為回報「完成」和寫程式的是同一個 Agent。

這場分享〈從 Vibe Coding 踩坑到培養共創默契：我用 Antigravity 打造產品的 UX、Agentic UX 與 AX 實戰〉從這類踩坑出發，談怎麼讓 Agent 知道改動範圍、哪些情況要先停下來，以及交付前要跑過哪些檢查。

## 改個顏色可以先跑，寄信給客戶要先停

Eva 用「單向門」和「雙向門」解釋，什麼時候該讓 AI 自己跑。改本機樣式是雙向門，做完再看，改壞了也容易復原。寄信給客戶就像單向門。按下送出之後，就算內容寫錯，也很難把對方收到的信收回來。

她把 Agent 自己寫程式、執行檢查、失敗後再修的過程稱為 **Inner Loop**。當工作牽涉外部資料、排程或交付，就得在整條流程裡安排檢查與確認。對我來說，這正是 **Agentic UX** 很具體的一部分。我能不能看出 Agent 現在跑到哪一步？發現方向錯了，能不能叫它停下來？如果下一步會對外產生影響，我有沒有機會先看過再確認？

以我熟悉的 Vue 專案來說，改按鈕的顏色，我會讓 Agent 做完後一起看差異。如果改的是表單的送出行為，我會先確認資料要送到哪裡、會不會觸發通知，再用測試環境驗證。兩個改動在程式碼裡都可能只有幾行，影響範圍卻差很多。

## 把開發默契寫進 AGENTS.md

Eva 遇過幾種很熟悉的狀況。新對話得重新交代之前的決定，改了 A 卻弄壞 B，介面做得像完成品，底下的資料卻還要再確認。她也提到，對話脈絡在執行中被壓縮後，Agent 有時會反覆卡在同一個步驟，有時會提早說做完了。

她後來把規則寫進 `AGENTS.md`，區分資料與運算邏輯，以及 UI 與視覺規範。做新頁面時，先確定要用哪些資料和計算結果，再安排版面和呈現內容。修改舊頁面時，先判斷要動的是資料邏輯、版面還是文案。她也提到共用資料和元件的做法。畫面上有好幾個地方需要同一份資料時，就讓它們讀同一個來源，省得以後得追著改好幾份。字級、留白和元件樣式則等頁面架構穩定後再收進設計系統。她會先讓 AI 提出比例，再由自己決定哪些要成為共用規範。

我把這理解成 **脈絡工程（Context Engineering）** 在專案裡的做法。把資料來源、改動範圍和驗收方式留在專案裡，換了對話，也還有地方可以查。這也接到 Eva 談的 **AX（Agent Experience）**，也就是人怎麼把任務、規則和回饋交給 Agent，讓它有足夠的資訊接著做。

我平常做規格驅動開發，最想帶回去的是把「這次哪些地方不用動」寫得更具體。以調整表單欄位間距為例，我會把版面改動和驗收放在同一張任務裡。

- 只改這個頁面的欄位間距，沿用現有元件與設計變數。
- 保留既有驗證規則、送出格式和共用元件的行為。
- 交付時列出改動檔案和實際跑過的檢查。真機驗證如果還沒做，就標記為待驗證。

## 外部資料和操作權限，要在流程上拆開

Eva 分享了一次讓她意外的經驗。她說自己在文字框打了另一項修改，還沒送出，Agent 就在回報時說已經順手改了。她也遇過 Agent 未經確認就修改甚至刪除資料庫內容。這些是她在開發時遇到的個案，帶出的問題很直接：Agent 在這一步能讀到什麼，又能動到什麼？

她後來把外部資料的擷取、清理與呈現拆成不同階段，先在受限的環境處理原始資料，再把清理過的結果交給後續流程。網頁、圖片等外部內容可能夾帶文字指令，因此她特別在意讀這些資料的環節有哪些權限。

這也讓我想到，`AGENTS.md` 可以把規則講清楚，權限設定則能把改動限制在預期的地方。以資料庫為例，只需要讀資料的工作，就用唯讀權限。真的有寫入或刪除的需求，再讓具備權限的步驟處理，並在執行前確認影響範圍。

## 測試可以交給 Agent，手機得自己拿起來滑

Eva 會讓 Agent 按照測試腳本執行檢查，發現問題就修正再測。她也試過提供幾種使用者角色，請 Agent 模擬這些人會如何操作網站。這些模擬可以幫我想到遺漏的情境，例如第一次填表的人能不能看懂錯誤訊息，或是在送出失敗後，是否知道可以從哪裡重來。

Q&A 有人問工程師要不要學設計。Eva 回到一個前端很熟悉的例子：響應式網頁（RWD）做完，最好拿實際的 Android 手機或 iPhone 操作一次。桌機上縮窄瀏覽器可以先看版面，我自己會再用真機試試鍵盤彈出後是否擋住欄位、錯誤訊息出現後畫面會捲到哪裡，以及單手能不能順利按下送出。

以前我交辦給 AI 時，容易把重心放在「講清楚要做什麼」。這場聽完，我想把「做到哪一步算完成」也提早寫進規格。下次 Agent 回報表單改完，我想看到的是它改了哪幾個檔案、跑過哪些情境，以及還有哪些操作等我拿手機確認。
