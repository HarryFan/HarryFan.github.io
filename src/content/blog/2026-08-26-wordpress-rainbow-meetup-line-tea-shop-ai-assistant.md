八月的 WordPress 彩虹小聚，還是在萬華的「可能存在的遊樂園 CollaPlay」。題目叫〈大缺工時代，每個小老闆都要擁有的 AI 行政助理〉，講者是文凱 Kevin——天羽新創的創辦人，也是 LUNA 品牌的創辦人，自我介紹那頁寫的是「AI 家教・自動化・內容系統」，一句 slogan：「讓 AI 替你打工，把時間還給更重要的事」。

活動頁把痛點講得很直接：你開店、做品牌、做電商，一天到晚耗在回訊息、對帳、盤庫存，明明該花時間想品牌下一步，卻永遠被瑣事追著跑。Kevin 的解法不是再叫老闆學一個新工具，而是把一間茶行的客服、記帳、進銷存、報表，全部搬進老闆本來就整天開著的 LINE。

主持人是哲北，開場照例先自我介紹一輪，害羞的 I 人可以 pass。整場分成兩段：前半段是 ChatGPT 的 GPT Live 和 Plugin 怎麼用，比較像暖身；後半段是重頭戲——現場掃 QR code 加茶老闆機器人好友，每個人拿到自己的示範帳本，跟著新手任務一路玩下去。我把後半段記得比較細，因為那些「為什麼這樣設計」的理由，比機器人本身更值得抄。

![我正把整間店連同帳本、紙箱一起塞進手機的對話框裡](/blog/2026-08-26-wordpress-rainbow-meetup-line-tea-shop-ai-assistant/04-shop-into-line.png)

## 前半段：先用 Live 把需求說清楚，再用 Plugin 把工具接起來

### GPT Live：直接用說的

GPT Live 是 ChatGPT 的語音對話模式。Kevin 的定位是「把 ChatGPT 變成可對話的 AI 夥伴」：直接用說的，可以即時追問、打斷、修正，適合教學、陪練、思考這三種場景。使用 SOP 五步：打開 ChatGPT → 進入 Live／語音 → 先設定角色 → 直接開始對話 → 隨時追問與修正。

關鍵在第三步。他給了一個「角色設定 4 格公式」：

> **角色 + 目標 + 方式 + 規則**
> 你是誰？／你要幫我什麼？／怎麼跟我互動？／有什麼限制？

這四格我覺得可以直接當 system prompt 的骨架用。平常寫提示詞最常漏的是第三格和第四格——你要它一次講完還是一問一答？哪些事不准做？沒講清楚，AI 就用它預設的方式跟你互動，然後你就會覺得它很煩。

### Plugin：讓 ChatGPT 開始幫你做事

第二部分是連結外掛程式。Plugin 能做的事他收斂成三件：找文件、整理重點、修改文件，Google Docs／Sheets／Slides 都能串起來。接 Google Drive 也是五步：打開 Plugins／Apps → 搜尋 Google Drive → Connect 並登入 Google → 允許權限 → 回到 ChatGPT 開始使用。

這段收在「今天帶走 3 件事」：先用 Live 把需求說清楚；再用 Plugin 把工具接起來；最後做成可複製的 AI 工作流。底下一行小字是「從問問題，到完成工作」——這句其實就是整場的主題：AI 不能只停在回答問題，要能動手把工作做完。

## 後半段：把一間店搬進 LINE

### 難的不是「記」，是「算」

開場先問大家：現在你怎麼記帳？手寫本子？Excel？記在腦子裡？還是根本沒記？月底，你算得出「這個月賺多少」嗎？

然後點出痛點：帳散在三個地方。記在腦子裡的——「剛剛好像賣了兩包……」忙起來就忘；寫在紙條上的——隨手一張單，月底湊不齊；線上訂單在別的後台——要自己去對，兩邊兜不起來。三邊都記一點，月底對不起來，「這個月賺多少」就答不出來。

![我拿著腦子、紙條、後台三張碎片在拼，怎麼拼邊都對不上](/blog/2026-08-26-wordpress-rainbow-meetup-line-tea-shop-ai-assistant/01-three-ledgers.png)

### 為什麼是 LINE

因為老闆本來就整天在 LINE 上，不用學新 App、不用開電腦。同一個對話框，能客服，也能顧一整間店的帳：

    <tr><th>功能</th><th>做什麼</th></tr>
  </thead>
  <tbody>
    <tr><td>客服</td><td>自動回覆、常見問題</td></tr>
    <tr><td>記帳</td><td>一句話記一筆進貨／賣出</td></tr>
    <tr><td>進銷存</td><td>庫存、成本、毛利自動算</td></tr>

  </tbody>
</table>

這個選擇對接案的人很有啟發。我們習慣先想「要做一個什麼系統」，Kevin 想的是「老闆現在人在哪裡」——系統就搬去那裡。工具越不像新工具，老闆越會天天用。

### 一個 bot，兩種身分

加好友之後先選身分：「我要買茶（客人）」或「試用老闆系統」。選試用，系統就發你一份自己的示範帳本，跟著「新手任務 1/5」走，不用人教。

設計理由是：客人只看得到品項和售價，老闆才看得到成本和毛利。同一支機器人，兩個世界——所以可以放心把它給客戶用。

### 任務 1、2：查庫存、賣出用點的

查庫存：點下面選單的「查庫存」，每支茶列出庫存幾包、均本多少、值多少錢，最上面是整間店的庫存總市值。老闆最想知道的「我現在有多少貨、值多少錢」，一句話就到。

賣出：點「賣出」→ 點要賣哪支茶 → 問你幾包 → 問你售價 → 跳出確認卡，卡片上已經幫你算好營收、成本、毛利。他的理由是：不用背指令、不用打完整句子，**點三下就記一筆——這樣老闆才會天天用**。

### 任務 3：用講的（然後 AI 聽錯了）

這是整場我覺得最精彩的一頁，投影片標題就直接寫「然後 AI 聽錯了」。

按著麥克風說「阿里山75 進10包 每包300」，AI 聽成「阿里山75近18,美方300」——錯得離譜。但它沒有直接記帳，它跳出確認卡問你。投影片上這段我逐字抄下來：

> AI 一定會聽錯。所以它只負責「聽」，不負責「記」。確認卡就是那道安全閘——這是整個系統最重要的一個設計。

![投影片：任務 3 用講的，AI 聽錯了，但它沒有直接記帳，確認卡才是安全閘](/blog/2026-08-26-wordpress-rainbow-meetup-line-tea-shop-ai-assistant/photo-slide-voice-confirm.jpg)

很多 AI 產品的 demo 都在證明「我聽得多準」，Kevin 反過來，在 demo 裡故意讓它聽錯，然後給你看它錯了也不會出事。把「聽」和「記」拆成兩個權限，中間卡一個人類點確認——這就是人機分工該長的樣子。Ruby 那場講的「Agent 做到 80%，把需要決策的 20% 交回來」，在這裡變成一張卡片。

![我守著閘門，麥克風那頭的話全變成亂碼堆在門外，帳本在門內安安靜靜](/blog/2026-08-26-wordpress-rainbow-meetup-line-tea-shop-ai-assistant/02-confirm-gate.png)

### 它還會提醒你「帳不對」

賣出時庫存不夠，紅字警告：「庫存只剩 0 包，賣出後會變負（是否還沒補記進貨？）」。但你仍然可以確認——負庫存是合法的臨時狀態。

理由：系統不幫你做決定，但會提醒你。負庫存等於你忘了補記進貨，月底盤點時就知道要補。這一點跟確認卡是同一套哲學：系統負責把異常攤在你眼前，決定權留給人。

### 任務 4：進貨，移動加權平均

點「進貨」→ 選茶 → 幾包 → 每包成本，確認卡算好這批的總成本；確認後庫存和平均成本自動更新。進新貨時，系統把新舊成本混成一個平均價（移動加權平均），這樣賣的時候才算得出真毛利。

### 任務 5：記錯了＋看報表

打「最近」看編號，打「沖正 編號」取消那一筆；打「今日」看今天營收、成本、毛利；報表還能匯出 Excel。

> 帳本只加不改：錯了不塗改，補一筆沖正把它沖掉。每一筆都留痕跡——月底、報稅都查得到。

工程師聽到這句應該很熟：這就是 append-only log。不准 UPDATE、不准 DELETE，錯了就再 INSERT 一筆反向的。Kevin 沒有講這些名詞，他講的是「報稅查得到」——同一件事，用老闆聽得懂的語言講。

![投影片：任務 5 記錯了＋看報表，帳本只加不改，補一筆沖正](/blog/2026-08-26-wordpress-rainbow-meetup-line-tea-shop-ai-assistant/photo-slide-reversal-report.jpg)

![我一腳把橡皮擦踢下桌，另一手在帳本最底下蓋一筆沖正](/blog/2026-08-26-wordpress-rainbow-meetup-line-tea-shop-ai-assistant/03-append-only.png)

### 隨便玩，不怕弄壞

打「重置試用」，示範帳本回到最初狀態；「切換身分」隨時換成客人視角。試用帳本是你自己的沙盒，不會動到老闆的真帳——所以他敢叫全場現場亂玩。給客戶一個可重置的沙盒，比任何說明文件都能讓人放心上手。

## Q&A 我記下來的

Q&A 的錄音收得不完整，我只記幾個有把握的：

- **活動報名也讓 AI 代勞。** Kevin 示範他把報名網址和名單檔案丟給 AI，AI 照著試算表格式讀資料、自動在網頁上一個一個點報名，底下留完整操作紀錄。原本手動要兩三個小時，現在 AI 跑大概一小時，而且他完全不用盯。同樣的路數，讀檔、寫檔、跨系統搬資料都能這樣做。
- **LINE 官方帳號能不能把進來的客人抓出來？** 可以。透過 webhook 收到 user ID、名字等資料存下來，後面要做 CRM 或分群都有底。
- **內容系統怎麼做到「像真人」？** 他們另一條產品線是幫客戶產 Threads 貼文。不是單一模型一次生成，而是多個模型分工：先拆這則貼文的架構和原因，再用人設去寫，步驟固定化之後兩三分鐘出一篇。有人問為什麼不再自動一點，連留言都自動掃、自動回？兩個限制：平台限制——Threads 很反全自動操作，跑太快會被管；品牌限制——品牌未必想自動跑去別人家底下留言，會影響形象。所以最後一哩還是留給品牌或客戶自己發。
- **Token 誰付？** 服務是訂閱制，一季五萬，服務費含 token，客戶不用另外燒。我聽完覺得這個商模滿不錯的：跟請人比就知道，一個員工月薪抓 36,000，一季就是 108,000；這套服務一季五萬，不到請人的一半，對小老闆來說划算許多。
- **資料是即時的嗎？** 資料寫入是即時的，同步到 LINE 那端是每兩分鐘抓一次；平台對請求頻率有限制，實務上一小時內的落差可以接受，兩分鐘已經很夠。

## 閃電講

中場休息前，主持人哲北開放閃電講報名，每人五分鐘，共六位，害羞的也可以上來廣告自己的品牌。我也報了一個。這裡記其中一場——一位接案七年的自由工作者，講的是他當天下午剛照完的 X 光片。

久坐加上愛喝茶，快 38 歲，落枕越來越頻繁，某天早上蹲廁所一個角度脖子就「砰」一聲左右轉不了。整復師叫他趁年輕去照 X 光，結果是骨質密度不足、頸椎和腰椎都有狀況。醫生講的兩個元兇：一是長期久坐——花五萬多買人體工學椅也沒用，一忙起來就不會站起來；二是茶和咖啡裡的成分會抓住鈣質，讓身體吸收不到。醫囑：復健做牽引、多游泳（尤其自由式）、少喝茶咖啡、多吃豆干、小魚乾、芝麻粉加無糖豆漿補鈣，然後——每工作一段時間就站起來動一動。他最後那句是「錢要賺，身體也要顧」。

一場講 AI 行政助理的聚會，被一個做了七年接案的人用一張 X 光片收尾。滿好的提醒。

## 我帶走的東西

- **AI 只負責聽，不負責記。** 確認卡是這套系統最值得抄的設計，把「辨識」和「寫入」拆成兩個權限，中間永遠卡一個人。做任何 AI 自動化都可以先問：哪一步是不可逆的？那一步前面有沒有一張確認卡？
- **系統搬去老闆在的地方，不是叫老闆搬過來。** 不用學新 App、點三下記一筆、可重置的沙盒——三件事都在降低「老闆會不會天天用」的門檻。功能做得再完整，沒人天天用就是零。
- **帳本只加不改。** 沖正、負庫存合法但會警告、每筆留痕跡——這些都是工程上的老原則，Kevin 用「報稅查得到」翻譯給老闆聽。跟客戶講話的時候，要講他的語言，不是我們的。
- **角色 + 目標 + 方式 + 規則**，四格公式拿回去改我的 system prompt 模板。
- 該去照個 X 光了。

場地與費用謝謝 Akamai、X Platform 職能共學平台、方舟計畫 Project Ark、MoksaWeb。彩虹小聚歡迎所有人，不分性別、族群，只要有一顆友善的心。下個月見。
